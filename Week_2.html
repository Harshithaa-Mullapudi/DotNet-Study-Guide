Part 1 — ASP.NET Core Fundamentals

What is ASP.NET Core?

ASP.NET Core is Microsoft's cross-platform framework for building modern web applications, Web APIs, backend services, real-time applications and other server-side solutions using .NET and languages such as C#.

Why use ASP.NET Core?

  • Cross-platform: Windows, Linux and macOS.
  • High performance and scalable.
  • Built-in dependency injection.
  • Middleware-based request pipeline.
  • Configuration, logging and environment support.
  • Works naturally with REST APIs and JSON.

C# vs .NET vs ASP.NET Core

TermMeaning
C#Programming language used to write application code.
.NETPlatform/runtime, libraries and tooling used to build and run applications.
ASP.NET CoreWeb framework on top of .NET for web apps and APIs.
Remember: C# is the language → .NET is the platform → ASP.NET Core is the web framework.

Types of applications

Web APIs, MVC web apps, Razor Pages, real-time applications, minimal APIs and backend services are common ASP.NET Core workloads.

Part 2 — Internet & Web Fundamentals

Internet, Web and Client–Server

The Internet is the global network infrastructure. The Web is a system of resources and communication built on top of the Internet, primarily using HTTP/HTTPS.

Browser / Client→HTTP Request→Web Server→HTTP Response→Client

Protocols

Protocols define communication rules. HTTP/HTTPS are used for web communication; DNS resolves domain names to network addresses.

DNS

DNS translates human-friendly domain names into IP addresses so clients can locate servers.

URL structure

https://example.com:443/api/students/10?grade=A#details
  • https — scheme/protocol
  • example.com — host/domain
  • 443 — port
  • /api/students/10 — path
  • ?grade=A — query string
  • #details — fragment

Web servers

Kestrel is ASP.NET Core's cross-platform web server. IIS, Nginx and Apache can also be involved in hosting/reverse-proxy architectures.

localhost and ports

localhost refers to the current machine. A port identifies a network endpoint for an application. Example: http://localhost:5257.

Status codes

Statelessness

HTTP is stateless: each request contains the information needed to process it; the protocol itself does not require the server to remember previous requests.

Safe vs Idempotent

Safe means the method is intended not to modify resource state. Idempotent means repeating the same request has the same intended effect on server state. GET, PUT and DELETE are generally idempotent; POST generally is not.

HTTPS/TLS

HTTPS is HTTP protected by TLS, providing encryption and server authentication.

Part 4 — REST & Web API Fundamentals

API vs Web API

An API is a contract/interface for software communication. A Web API exposes functionality over web protocols, commonly HTTP.

REST

REST is an architectural style for designing networked applications around resources and uniform interactions.

Resource and Endpoint

A resource is a domain object such as Student. An endpoint is an HTTP-accessible operation identified by method + route.

GET /api/students
GET /api/students/10
POST /api/students
PUT /api/students/10
DELETE /api/students/10

CRUD

Create, Read, Update, Delete.

Route vs Query Parameters

/api/students/10 uses a route parameter to identify a specific resource. /api/students?grade=A uses a query parameter to filter/customize a collection.

REST constraints

  • Client–Server
  • Stateless
  • Cacheable
  • Uniform Interface
  • Layered System
  • Code-on-Demand is optional

Mnemonic: CSC ULC — Client-Server, Stateless, Cacheable, Uniform Interface, Layered System, Code-on-Demand.

HATEOAS

Hypermedia as the Engine of Application State: responses can provide links/actions that help clients discover related resources.

RESTful API: A Web API designed to follow REST principles, using resources, HTTP methods, stateless interactions and meaningful representations/status codes.

HttpContext

HttpContext represents the current HTTP request/response context. It gives access to request, response, user, connection, per-request services, items and lower-level features.

Important Program.cs methods

  • app.UseHttpsRedirection() redirects HTTP requests to HTTPS when configured; it is not simply “redirecting ports.”

OpenAPI

OpenAPI describes an HTTP API in a machine-readable format. In the newer template, app.MapOpenApi() can expose an OpenAPI document such as /openapi/v1.json. Swagger UI is a separate interactive UI that can consume an OpenAPI description.

Part 7 — Controllers

What is a Controller?

A controller is a class that handles HTTP requests and produces HTTP responses for API endpoints.

ControllerBase vs Controller

ControllerBase provides API-oriented controller features. Controller extends it with MVC/view-related capabilities. Web APIs commonly use ControllerBase.

[ApiController]

Marks a controller as an API controller and enables API-specific conventions/behaviors such as automatic model-validation responses and binding inference.

[Route]

Defines a route template. [Route("api/[controller]")] uses the controller name token.

Action Methods

Public controller methods that respond to HTTP requests when matched by routing.

HTTP action attributes

[HttpGet], [HttpPost], [HttpPut], [HttpPatch], [HttpDelete] associate actions with HTTP methods.

Endpoint formula: HTTP method + route template + action/endpoint mapping.

Part 8 — C# Attributes in ASP.NET Core

What is an Attribute?

A C# attribute attaches metadata to a class, method, property, parameter or other code element. ASP.NET Core reads this metadata to configure behavior.

Important attributes

AttributePurpose
[ApiController]API-controller behavior.
[Route]Route template.
[HttpGet] etc.HTTP method mapping.
[FromRoute]Bind value from route.
[FromQuery]Bind from query string.
[FromBody]Bind from request body.
[FromHeader]Bind from header.
[FromForm]Bind from form data.

Route templates

[Route("api/[controller]")]
[HttpGet("{id:int}")]

{id} is a route parameter. :int is a route constraint. Controller-level routes can combine with action-level route templates.

Part 9 — Routing & Endpoint Routing

Routing

Routing matches an incoming HTTP request to an endpoint.

Route template vs actual URL vs endpoint

TermExample
Route template/api/students/{id}
Actual request/api/students/10
EndpointGET /api/students/{id}
Route valueid = 10

Endpoint Routing

ASP.NET Core's endpoint routing system builds a set of endpoints and matches incoming requests against them.

Registration vs Matching

MapControllers() maps controller endpoints into the endpoint system. When a request arrives, routing matches the request to the appropriate endpoint.

HTTP method matching

The same path can have different endpoints for different methods, e.g. GET and POST.

Constraints and ambiguity

Constraints such as {id:int} narrow route matches. Ambiguous routes can cause an ambiguity error when more than one endpoint matches equally.

Routing vs Model Binding

RoutingWhich endpoint/action should handle this request?
Model BindingWhat values should be supplied to that action's parameters/models?

Query strings generally do not change route matching: GET /api/students?grade=A still matches /api/students.

An action result represents the HTTP response produced by a controller action.

IActionResult

IActionResult is an abstraction that allows an action to return different HTTP result types.

ActionResult<T>

ActionResult communicates that a successful result can contain a Student while still allowing other HTTP results such as NotFound.

Object serialization

When you return an object such as Ok(student), ASP.NET Core processes the result and serializes the object to JSON for the HTTP response.

Part 12 — Model Binding

Definition

Model binding takes values from an HTTP request and supplies them to controller action parameters or models.

Binding sources

  • Route values
  • Query string
  • Request body
  • Headers
  • Form data

Binding attributes

[FromRoute], [FromQuery], [FromBody], [FromHeader], [FromForm].

Automatic binding and [ApiController]

ASP.NET Core can infer common binding sources. [ApiController] provides API-specific binding inference/conventions.

Type conversion

Binding can convert incoming values to target C# types when possible. For example, route text "25" can become int 25.

Binding vs JSON deserialization

DeserializationModel Binding
JSON/data format → C# object.HTTP request data → action parameter/model.
Specific data-format concern.Broader request-data process.
Important: A route constraint can prevent an endpoint match before binding. A binding conversion failure can instead create model-state errors; with [ApiController], invalid model state commonly results in 400.

Part 13 — Middleware

What is Middleware?

Middleware is a component in the ASP.NET Core request pipeline that can inspect/modify requests and responses, perform work before/after the next component, or terminate the pipeline.

Cross-cutting concerns

Logging, exception handling, authentication, authorization, security, caching and compression are examples.

Short-circuiting

A middleware short-circuits when it chooses not to call the next component and completes the response itself. It is not synonymous with an exception.

RequestDelegate

RequestDelegate represents a method/delegate that processes an HttpContext, commonly representing the next pipeline step.

HttpContext components

PropertyPurpose
RequestIncoming HTTP request.
ResponseOutgoing HTTP response.
UserIdentity, claims and authentication state.
ItemsTemporary per-request storage.
ConnectionConnection information.
RequestServicesDI services available for the request.
FeaturesLower-level server/framework capabilities.

Use, Run and Map

  • Use() — middleware that can run before/after and call next.
  • Run() — terminal middleware; doesn't continue the pipeline.
  • Map() — branches the pipeline for a path/predicate.

Ordering

Middleware order matters because each component sees the request/response at its position in the pipeline.

Built-in middleware concepts

Exception handling, HTTPS redirection, static files, routing, authentication, authorization and response compression.

Authentication vs Authorization

Authentication: Who are you? Authorization: Are you allowed to perform this action?

Kestrel

Kestrel receives HTTP/HTTPS requests, participates in creating request context, passes requests into the ASP.NET Core pipeline and sends responses back to clients.

Pipeline lifecycle: The pipeline is configured at startup and reused across requests; each request gets its own HttpContext.

Part 14 — Dependency Injection

Dependency

A dependency is something a class needs in order to perform its work.

Dependency Injection

DI provides dependencies from outside the class instead of the class constructing them itself.

Benefits

  • Loose coupling
  • Easier testing
  • Replaceable implementations
  • Better maintainability
  • Separation of responsibilities

Types of injection

  • Constructor injection — preferred/common in ASP.NET Core.
  • Property injection
  • Method injection

DI Container

The DI system manages registrations, creates/resolves objects and manages their lifetimes.

builder.Services

builder.Services is the service-registration collection used to configure the DI container.

Service lifetimes

LifetimeMeaning
TransientNew instance each time it is requested.
ScopedOne instance per HTTP request/scope.
SingletonOne instance for the application lifetime.

Registration methods

AddTransient(), AddScoped(), AddSingleton().

Interfaces and DI

Interfaces are often used to reduce coupling and make testing/replacement easier.

RequestServices

HttpContext.RequestServices provides access to request-scoped services. Constructor injection is generally preferred over manually resolving services.

Project decision: Our current Student Management System does not introduce a separate StudentService layer yet. DI is being learned as a concept and through framework infrastructure such as logging.

Part 15 — Configuration

Configuration Fundamentals

Configuration is data/settings that control application behavior without changing application code.

Application LogicDefines what the application does.
ConfigurationProvides values/settings used by that behavior.

Common sources

  • appsettings.json — base configuration.
  • appsettings.Development.json — environment-specific overrides.
  • User Secrets — development-time secrets.
  • Environment variables — deployment/runtime configuration.
  • Command-line arguments — runtime overrides.
  • Custom providers — database, REST API, etc.
  • Azure Key Vault — secure secret/key/certificate management.

Hierarchical configuration

{
  "StudentSettings": {
    "MaxStudents": 100,
    "DefaultGrade": "A"
  }
}

Keys conceptually become StudentSettings:MaxStudents and StudentSettings:DefaultGrade.

IConfiguration

IConfiguration is a unified abstraction for reading configuration from multiple providers.

Reading configuration

  • Indexer: configuration["StudentSettings:MaxStudents"]
  • GetValue<T>() — reads/converts a typed value.
  • GetSection() — gets a configuration section.
  • IConfigurationSection — represents a specific section.
  • GetChildren() — gets child sections.

Provider precedence

appsettings.json
      ↓
appsettings.{Environment}.json
      ↓
User Secrets
      ↓
Environment Variables
      ↓
Command-Line Arguments

Later providers override earlier values for the same key in this simplified ordering.

Environment variables

StudentSettings__MaxStudents maps to StudentSettings:MaxStudents. Double underscore __ represents hierarchy.

Strongly Typed Configuration

Configuration can be bound to a C# class. The binder maps matching configuration keys/properties. Extra configuration values are generally ignored; missing class properties retain defaults unless validation/defaulting changes the outcome.

Options Pattern

  • Configure<T>() — registers configuration for an options class.
  • IOptions<T> — basic options access.
  • IOptionsSnapshot<T> — scoped/request-based options, supporting updated values between requests when reload is supported.
  • IOptionsMonitor<T> — monitors changes and supports current values/change notifications.

Configuration validation

Binding maps values; validation checks whether those values satisfy rules. Data annotations such as [Required] and [Range] or custom validation can be used.

User Secrets vs Azure Key Vault

User SecretsAzure Key Vault
Primarily local development.Secure centralized secret/key/certificate management, commonly Azure/production.

Custom providers

A custom provider can load settings from a database, REST API or another custom source.

Model Binding vs Validation

Model BindingModel Validation
Gets data from HTTP request and supplies action parameters/models.Checks whether the supplied data is acceptable.

Data Annotations

Common validation attributes come from System.ComponentModel.DataAnnotations.

AttributeMeaning
[Required]A value must be provided.
[Range(5,100)]Value is between 5 and 100 inclusive by default.
[StringLength]Controls maximum/minimum string length.
[MinLength]Minimum length.

ModelState

ModelState contains information about model binding and validation, including errors. ModelState.IsValid is true when there are no model-state errors.

[ApiController]

For API controllers, invalid model state can automatically result in a 400 Bad Request response.

Binding vs validation errors

Binding errorAge = "hello" cannot be converted to int.
Validation errorAge = 150 is an int but violates [Range].

Custom validation

Built-in attributes handle common rules. Custom attributes, IValidatableObject and other validation mechanisms can handle application-specific rules.

Validation vs business logic

Validation asks “Is this input acceptable?” Business logic asks “What should the application do with valid input?”

Nullable reference types

string? indicates that C# allows null. [Required] expresses an application validation requirement. They are related but not the same mechanism.

Part 17 — Global Exception Handling

Exception

An exception is an unexpected runtime problem, such as NullReferenceException, InvalidOperationException, FormatException or ArgumentException.

Validation vs Exception

ValidationException
Expected invalid input.Unexpected runtime/application failure.
Often 400.Often 500.

Why global exception handling?

  • Consistent error responses
  • Less duplicate try/catch code
  • Security
  • Centralized logging
  • Maintainability

Exception middleware

Because middleware surrounds deeper pipeline components, exception handling middleware can catch/observe unhandled exceptions and convert them into safe HTTP responses.

UseExceptionHandler

UseExceptionHandler is built-in ASP.NET Core middleware for handling unhandled exceptions centrally.

Developer Exception Page

Useful in Development for detailed debugging information. Do not expose detailed internal exception information to production users.

Problem Details

Problem Details provides a standardized structure for HTTP API errors, commonly containing type, title, status, detail and instance.

Exception vs Problem Details

An exception is an internal runtime failure. Problem Details is an HTTP response representation used to communicate an error to a client.

Known vs unexpected errors

Not every exception necessarily maps to 500. A known application condition such as a not-found condition can be mapped to 404 when appropriate. Unexpected infrastructure/application failures commonly become 500.

Security

Do not expose stack traces, connection strings, internal paths, SQL details or other sensitive implementation details to production clients.

Typical flow: Exception → global handler → log detailed information → create safe HTTP response/Problem Details → client.

Part 18 — Logging

Logging Fundamentals

Logging records information about what is happening inside an application. A log is one recorded event/message.

Logging vs Debugging

Debugging is active investigation using tools such as breakpoints and variable inspection. Logging records information that can be reviewed later.

Logging vs Exception Handling

Exception handling decides how to handle a failure. Logging records information about what happened. They commonly work together.

Why Console.WriteLine is insufficient

  • No standard log levels.
  • Weak filtering capabilities.
  • Not structured by default.
  • No flexible provider architecture.
  • Harder integration with centralized monitoring and production systems.

ILogger

ILogger is the logging abstraction used by .NET applications. Application code does not need to know which provider ultimately stores or displays the log.

ILogger<T> and categories

ILogger<StudentsController> associates the logger with a category based on the type. Categories help filtering and identifying log sources.

DI and logging

Logging is integrated with DI. Controllers/components commonly receive ILogger<T> through constructor injection.

Logging providers

  • Console Provider
  • Debug Provider
  • Event Source Provider
  • Event Log Provider
  • Azure Monitor / Application Insights overview
  • Third-party: Serilog, NLog, log4net

Log levels

LevelMeaning
TraceVery detailed diagnostics.
DebugDeveloper-focused diagnostic information.
InformationNormal important application activity.
WarningConcerning/unusual situation, but operation can continue.
ErrorA specific operation failed.
CriticalSevere failure affecting major functionality or requiring urgent attention.

Filtering

Log filtering controls which levels/categories/providers are processed. Example: production may use Information and above while noisy framework categories may be limited to Warning.

Logging configuration

Logging can be configured through appsettings.json, including default log level, category/namespace filtering and provider-specific filtering.

Structured Logging

Structured logging uses message templates and named properties.

"Student {StudentId} was retrieved"

Here StudentId can be preserved as structured data, improving searchability, filtering and analysis.

Exception logging

LogError() is appropriate for operation failures; LogCritical() is for severe failures. When logging an exception, pass the exception object when appropriate rather than only its message so useful exception information can be captured.

Logging internals

ILoggerFactory can create loggers. The category is commonly based on the type passed to ILogger<T>.

Best practices

  • Log important application events, failures, warnings and useful identifiers.
  • Do not log passwords, JWT tokens, API keys, secrets or connection strings.
  • Be careful with PII and other sensitive information.
  • Production logs should be useful, secure, appropriately detailed and searchable.

Logging Scopes

A scope associates shared contextual information with multiple log entries, such as a request identifier.

Correlation IDs

A correlation ID identifies a request/operation so related logs across components or services can be connected.

Distributed Tracing

Distributed tracing follows a request across multiple services/operations. A trace represents an overall operation; spans represent individual operations.

OpenTelemetry

OpenTelemetry is an open-source observability framework/ecosystem for collecting and exporting telemetry such as logs, metrics and traces.

Part 19 — LINQ & Querying

What is LINQ?

LINQ means Language Integrated Query. It provides C# syntax and operators for querying data from collections and other queryable data sources.

LINQ Execution Pipeline

Data Source
   ↓
LINQ Query
   ↓
Operators
   ↓
Execution
   ↓
Result

Deferred Execution

The query is defined but not executed until the sequence is enumerated or an immediate operator requests the result.

Immediate Execution

Operators such as ToList(), ToArray(), ToHashSet(), First(), FirstOrDefault(), Single(), SingleOrDefault(), Any(), All() and Contains() execute/produce a result immediately.

yield return

yield return creates iterator behavior, producing values one at a time as they are requested rather than returning the entire sequence from the method at once.

IEnumerable<T>

Represents a sequence that can be enumerated. LINQ-to-Objects commonly operates over in-memory collections using IEnumerable<T>.

IQueryable<T>

Represents a query that can be interpreted by a query provider. Entity Framework Core can translate suitable LINQ expressions into SQL so filtering can occur in the database.

IEnumerable<T>IQueryable<T>
Enumerable sequence; commonly in-memory.Query representation for a provider.
LINQ operations generally execute in application process.Provider may translate operations to source language.
LINQ to Objects.Commonly used by EF Core/database queries.

Searching Operators

OperatorBehavior
First()First element; exception if none.
FirstOrDefault()First element; default if none.
Single()Exactly one; exception if zero or multiple.
SingleOrDefault()Zero or one; default for zero, exception for multiple.
Where()All elements matching a condition.
ElementAt()Element at index; exception if index invalid.
ElementAtOrDefault()Element at index; default if invalid.

First vs Single

First means “give me the first match.” Single means “there must be exactly one match.”

Ordering

  • OrderBy() — primary ascending order.
  • OrderByDescending() — primary descending order.
  • ThenBy() — secondary ascending order.
  • ThenByDescending() — secondary descending order.
OrderBy(Grade)
ThenBy(Name)

First sort by Grade, then sort equal-grade records by Name.

Quantifiers

OperatorQuestion answered

All()Do all elements satisfy the condition?

Conversion / Materialization

  • ToList() → List<T>
  • ToArray() → T[]
  • ToHashSet() → HashSet<T> with uniqueness determined by equality semantics.

Self-check Quiz

1. What is the difference between C#, .NET and ASP.NET Core?
C# is the programming language; .NET is the platform/runtime and libraries; ASP.NET Core is the web framework built on .NET.
2. What does Kestrel do?
It is the ASP.NET Core web server that listens for HTTP/HTTPS traffic and passes requests into the ASP.NET Core pipeline.
3. What does [ApiController] provide?
API-specific conventions and behaviors, including binding inference and automatic 400 responses for invalid model state.
4. What is routing?
Matching an incoming HTTP request to an endpoint.
5. What is IActionResult?
An abstraction representing an HTTP result returned by a controller action.
6. What is serialization?
Converting a C# object into JSON or another representation.
7. What is model binding?
Taking data from the HTTP request and supplying it to action parameters/models.
8. What is middleware short-circuiting?
A middleware chooses not to call the next component and completes the response itself.
9. What are the three DI lifetimes?
Transient, Scoped and Singleton.
10. What is configuration precedence?
When multiple providers define the same key, the later provider in the configured precedence order overrides the earlier value.
11. What is the difference between binding and validation?
Binding supplies data to the model/parameters; validation checks whether that data satisfies rules.
12. Why use global exception handling?
To centralize error handling, avoid duplicate code, provide consistent safe responses, and support centralized logging.
13. What is ILogger?
A logging abstraction that lets application code write logs without being tightly coupled to a particular logging destination/provider.
14. What is structured logging?
Logging using message templates and named properties so data remains searchable and structured.
15. What is deferred execution?
The LINQ query is defined but execution is delayed until enumeration or an immediate/result-producing operation occurs.
16. First vs Single?
First returns the first match; Single requires exactly one match.
17. What does Any() answer?
Whether at least one element/match exists.
18. What does ToList() do?
Materializes the sequence into a List and forces execution of a deferred query.
